# singlefs-ai-sop-ja

**貢献者ガバナンス SOP の日本語版。**

**扱うのは「プロジェクトが AI とどう協働するか」**——提出物にどんな証拠を添えるか、
検索で誤読されない文書の書き方、決定をどこに記すか、ゲートが拒否するとき何を示すか。
これらは作っているものが何のシステムかとは無関係である。

**扱わないのは：ファイルシステムをどう設計するか。**
「トランザクションから始める」のような規律はプロジェクト側のものであり、
そのプロジェクトの `.claude/rules/` に置く。

**この SOP は singlefs のために作られたものであり、利用者は singlefs 一つだけで、
他のプロジェクトで通用することを前提にしていない。**
したがって判定基準は「他のプロジェクトもこれを必要とするか」ではない——
見るべき他のプロジェクトが無い以上、誰でも「する」と答えられる。
判定基準は、それが協働を扱うのか、ファイルシステムの設計を扱うのかである。

> **実装は AI に優しく、レビューは人間に優しく。**

## 自分の言語の版を選ぶ

**開発者は自分の言語に合った版を選ぶ。** 現在は中国語・英語・日本語があり、
他の言語版も準備中である。既定の版は英語。
入れたリポジトリの言語でそのまま作業する——日本語で作業する人が中国語を読む必要はない。
**AI もそこで訳し直す必要がない**：どの言語のリポジトリで働くかで協働の言語が決まる。
転記が一度減れば、情報の損失も一度分減る。これが多言語版を保つ理由のすべてである。

`I18N` の `this=` は本リポジトリの言語、`default=en` は既定の版、
`languages=` は公開済みの言語を示す。マニフェストとゲートスクリプトは中国語のリポジトリにある。

**一回の貢献は公開済みのすべての言語版を含む。** 貢献者がどの言語で書くかにかかわらず、
提出はすべての版を同時に変更し、同時にマージする。自分の言語だけを直した提出は受け取らない
——それは「他の言語の人が古い規則を受け取る」コストを他人に押し付けることになる。
**各版が同じことを言っているかは貢献者自身が保証する。**
ゲートに分かるのはハッシュの不一致だけである。

読み方が食い違う場合は言語で決めず、**`scripts/` の実際の挙動が決める**——
スクリプトはこれらの規則の唯一の曖昧さのない表明である。

**現状：中国語以外の版は機械翻訳である。** 素早く行き渡らせるためであり、
規範が正式版になる前に正確な翻訳を行う。

ある版の記述が悪い場合（ずれ、用語の不統一）はその版を直す——
**そして他の二つの版も不明瞭でないかを併せて確認する。**
言語ごとに露わになる曖昧さは異なる。三つを保つ副次的な価値であり、無駄にしない。

用語は三言語共通の [GLOSSARY.md](GLOSSARY.md) に従う。

## 変更のハードル

**この SOP は固まったあとはほとんど動かないはずである。** 参加者全員の共通の土台であり、
一条変えることは全員の下限を同時に変えることに等しい。
判断はすべて人が行う——SOP は準則であって被検証対象ではない。
本当の信号は**変更の頻度**であり、頻繁に変わるならそれは設計に問題がある証拠である。

**作業はこのリポジトリでは行わない。** 日常の作業は singlefs の中にある。
`0.x` は未確定を意味し、`1.0.0` 以降 `rules/` の変更は稀であるべきである。

## 同期の保ち方

`SOURCE-MANIFEST.sha256` は、このリポジトリを最後に足並みを揃えた時点のマニフェストの写しである。
マニフェストとスクリプトが置かれている中国語リポジトリの現在の `MANIFEST.sha256` と
比べれば、どのファイルが遅れているか分かる。
マニフェストは `CLAUDE.md` と `rules/*.md` を対象とする——
`CLAUDE.md` は規範本文であり、対話言語も定めているため、外すと三言語が黙って別のことを言い出す。
`VERSION` は三つのリポジトリで完全に一致し、一つ上げれば三つとも上がる。

## 導入

```bash
git clone https://github.com/faliye/singlefs-ai-sop-install
bash singlefs-ai-sop-install/sop-install.sh --lang ja
```

インストーラ自身の表示も、選んだ言語に従う。
