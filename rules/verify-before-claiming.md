# 外部の状態を述べる前に、その場で確認する

**「外部世界が今どうなっているか」に関する発言はすべて、
口に出す前にその場でコマンドを一つ走らせて確認すること。**
記憶、kb、前回の対話、TODO 表——いずれも手がかりであって、根拠ではない。

「外部世界」= この対話の中に無く、自分の知らないところで変更されうるもののすべて：

| 述べようとしていること | 今すぐ走らせるコマンド |
|---|---|
| ゲートが今通るかどうか | `scripts/gate.sh` を走らせる。前回の結果から推測しない |
| ある不変条件が実装済みかどうか | `kb/invariants.md` の状態列を読み、さらに checker のソースを grep して実在を確認する |
| ある決定が確定しているかどうか | `kb/decisions.md` を読み、確定 / 半確定 / 未確定のどれかを見る |
| ツールチェーンと環境が揃っているか | `scripts/env.sh` を走らせる |
| 他のファイルシステムがどうしているか | その文書かソースを今すぐ確認し、kb に出所と「本プロジェクトでは未検証」を記す |
| テストイメージの現在の状態 | その場で checker を走らせる。「前回は健全だった」に頼らない |

**その場で確認しなくてよいもの**：この対話の中で今読んだファイル、
純粋なコード論理の導出、算術。

## 「決まっているか」と「実際に何と定義されているか」は別の問いである

状態列を確認し、ある決定が「確定」であると分かったからといって、
**それが何を定めているかを知っていることにはならない。**
ある決定をモデル化に使う、検査を書く、別の結論を覆すために使う——
そのいずれであっても、**その定義文を一字一句読むこと**が要る。
自分の記憶に基づいてモデル化してはならない。

実測：ある実験は、ある決定が新しい場面でエラーを起こすかどうかを測ろうとした。
モデル化の際、自分の理解に基づいて二通りのあり得る意味を作り、
「どちらもエラーになる」という結果を得て、それを根拠にその決定を覆した。
ところが**その決定の本文にはすでに第三の定義が書かれていた**——
それに従って走らせればエラーは常にゼロであり、結論全体の向きが逆であった。
後から振り返ると：状態列は確認していたが、定義は読んでいなかった。

**やり方**：ある決定を引用して何らかの推論を行う前に、
その定義文をそのままメモか実験のコメントに貼り付けること。
貼り付けられないなら、記憶だけで作業している証拠である。

## 狭いほうを確認し、口に出したのは広いほうだった

これは自分では最も気づきにくい。**「その場で確認する」という手順は本当に踏んでいる**
——コマンドを走らせ、ファイルを読み、確かに検証済みの命題を手にしている。
**誤りは、そのあとに述べた文がそれより広いことにある。**

**実測 2 件（2026-09-10、同日・同一人物）**：

| 確認したこと（狭い、真） | 口に出したこと（広い、偽） | 代償 |
|---|---|---|
| 「`sudo` がサンドボックスに阻まれた」 | 「root が取れないので、この観測はできない」 | 同じリポジトリ内の別の経路は**その権限を必要とせず**、文書にも「実測済み」と一字一句書かれていた ⇒ **観測ゼロの一巡、しかも記録された理由が偽** |
| 「あるクラス規則の列挙にこの対象が載っていない」 | 「この枠はリポジトリ全体でどこにも根拠がない」 | **クラス所属は別の 2 ファイルに書かれており**、そのクラス規則は最初から対象を覆っていた ⇒ 実験の立て方が丸ごと無効、同じ未払い項目を**二度書き間違えた** |

どちらも形は同じ——**検証したのは一つの経路 / 一つのファイル、断言したのは全経路 / 全リポジトリ。**

⇒ **判定基準：これから言う文の主語と範囲は、いま確認したものとまったく同じか。**

- 「この経路は通らない」を確認した ⇒ 言えるのは「この経路は通らない」だけで、
  **「できない」ではない**。
- 「このファイルには書かれていない」を確認した ⇒ 言えるのはそれだけで、
  **「リポジトリのどこにもない」ではない**。

⇒ **やり方**：広いほうの文を証明すべき命題として置き、
**「これが真であるためには、どの場合を排除する必要があるか」**を問い、一つずつ潰す。
潰しきれなければ、実際に潰した範囲まで文を縮める——
**縮めた文はなお使える。広くて偽の文は、その一巡全体の土台になってしまう。**

⚠️ 「この対象は条項に覆われているか」は特に嵌まりやすい。**条項は別の場所にあって、
クラス単位で覆っていることがある**——対象自身の節には一字も書かれていないまま。
⇒ 判断する前に**その名前でリポジトリ全体を grep** し、既存のどれかのクラスに
入れられていないか見る——**クラス規則が代わりに答えている。**

## 実践に落とす

- **kb や TODO の状態行を書き換える前に、その行に対応するコマンドを走らせる。**
  確認せずに書き換えない——古い行にはまだ日付が付いているが、
  書き換えれば誤った記述に新しい日付を与えることになる。
- 「どのコマンドで知ったか」を言えないなら、その一文は事実ではなく
  **推測**として書かねばならない。
- 利用者からの事実の訂正**も同様に確認する**——
  鵜呑みにもせず、反論もせず、確認した上で結果を明確に述べる。
