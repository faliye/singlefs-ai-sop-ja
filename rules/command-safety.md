# プロセスとコマンドの規範

## `pkill -f` / `killall` は一律禁止

パターン文字列はラッパー自身のコマンドラインにも現れるため、
**自分のシェルを殺す。**

プロセスを止めるには：まず `ps` で列挙して目で確かめ、
二つ目のコマンドで**リテラルの pid** を指定して殺す。
数を数える用途には `/proc` の構造化された判定を使い、自分のプロセスツリーを除外する。

## QEMU の仮想機は pid をファイルに書くこと

破棄する時はファイル内のリテラル pid で殺し、名前照合で殺してはならない。
暴走した仮想機はメモリを食い尽くし、名前照合は他のテストまで巻き添えにする。

## echo で成功を装わない

`cmd 2>/dev/null; echo "完了"` のその echo は**無条件に実行される**——
sudo が失敗していても「完了」と出る。

状態を変えるコマンドは必ず**実際の状態を読み戻して**検証する：
`systemctl stop X` の後は `is-active` で確認する。`stop` の終了コードだけでは足りない。

## 結果の回収には完全性のゲートを設ける

被テストプログラムが結果を印字し、外側のスクリプトが回収する——
**この経路で一行落ちるのは無言で起きる。**
コンソールは BIOS のエスケープシーケンス、カーネルログ、シリアルのノイズに汚染される。
行頭で錨を打つ（`grep '^ANCHOR'`）と、行頭を上書きされた行を黙って取りこぼす。
外から見えるのは「一項目少ない」であって「失敗した」ではない。

**やり方**：被テストプログラムが最終行で「合計何件出したか」を申告し、
回収側は件数を突き合わせ、合わなければその回を破棄する。
このゲート自体も先に赤くなることを証明しておく——
N 件出したと称して N−1 件しか出さない偽プログラムを食わせ、赤にならねばならない。

## サブシェル内の代入は親プロセスに戻らない

`rc="$(run_one ...)"` の形では、`run_one` が変数に代入しても**親では空**である。
結果の回収がその変数（ログのパスなど）に依存していれば、
回収件数は永遠にゼロのまま、終了コードは 0——またひとつ、緑のまま誤る。
**値を渡すならファイルに落とすこと。変数に頼らない。**

## テストイメージは必ず一時ディレクトリに置く

リポジトリ内には置かない。
数 GB のイメージを誤って git に入れるのは取り返しのつかない厄介事である。
イメージのパスは環境変数から取り、既定は `${TMPDIR:-/tmp}` とする。

## 破壊的な操作は、動かす前に目で確かめる

`mkfs` / `dd` / `dmsetup remove` でデバイス名を打ち間違えれば実データが消える。
**対象デバイスは変数から取り、先に `lsblk` で印字して確認すること。**
`/dev/sdX` のリテラルをハードコードしてはならない。
