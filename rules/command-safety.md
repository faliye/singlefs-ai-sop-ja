# プロセスとコマンドの規範

このうち四条はすでに赤くなる検査であり、注意書きではない——`scripts/shell-lint.sh` が判定する：
**パターン一致でプロセスを殺すこと**、**サブシェル内の代入で値を外に持ち出すこと**、
**スクリプト内で git の取り消し系コマンドを使うこと**、
**`rm -rf` を守りのない変数パスに当てること**。
残りはまだ文章のままである。機械判定の基準が定まっていないからだ
（`show-me-test.md`「ゲートが証明できること、できないこと」——
やっていないことは、ぼかさず言う）。

## 取り消せない操作は、手を出す前にもう一度考える

判定基準は一つだけ：**この一歩を踏んだあと、戻れるか。**

戻れないものは二種類あり、扱いが違う：

| 種類 | 例 | どうするか |
|---|---|---|
| **未コミットの変更を捨てる** | `git checkout <ファイル>`、`git restore`、`git reset --hard`、`git clean` | 先に `git stash` するか `cp` で外に控えを取る。そのファイルの未コミット変更を**全部**捨てると分かっているときだけ使う |
| **データを直接消す** | `rm -rf`、`> ファイル`、`sed -i`、`rsync --delete`、`mkfs`、`dd` | 先に対象を見る（`ls` / `git status` / `lsblk`）。変数のパスには `${VAR:?}` の守りを付ける |

**実際に踏んだ**：一時的な `sed` を取り消したいだけで `git checkout <ファイル>` を使い、
同じファイルのその回の未コミット変更を丸ごと消してしまった。
そのときは reflog に残っていた直前の commit から拾えたが、
その commit が無ければ失われていた。

**だから、使い捨ての実験は副本でやる。** 作業ツリーで書き換えてから戻そうとしない。

**スクリプトの中に git の取り消し系コマンドを書いてはならない。**
スクリプトが走っている間、誰も `git status` を見ていない。そしてこれらに undo は無い。
スクリプト内できれいな状態に戻したいなら、先に `git stash` するか、
リポジトリごと複製して副本の上でやる。

**`rm -rf` を変数のパスに当てるときは空値の守りを付ける。**
`rm -rf "$d/x"` は `$d` が空だと `rm -rf /x` になる。`rm -rf "${d:?}/x"` と書けば、
`rm` が動く前にシェルがエラーで止まる。
（`rm -rf "$d"` のように後ろにパスが続かないものは不要：空なら `rm -rf ""` となり、`rm` 自身が拒む。）

## `pkill -f` / `killall` は一律禁止

パターン文字列はラッパー自身のコマンドラインにも現れるため、
**自分のシェルを殺す。**

プロセスを止めるには：まず `ps` で列挙して目で確かめ、
二つ目のコマンドで**リテラルの pid** を指定して殺す。
数を数える用途には `/proc` の構造化された判定を使い、自分のプロセスツリーを除外する。

## QEMU の仮想機は pid をファイルに書くこと

破棄する時はファイル内のリテラル pid で殺し、名前照合で殺してはならない。
暴走した仮想機はメモリを食い尽くし、名前照合は他のテストまで巻き添えにする。

## echo で成功を装わない

`cmd 2>/dev/null; echo "完了"` のその echo は**無条件に実行される**——
sudo が失敗していても「完了」と出る。

状態を変えるコマンドは必ず**実際の状態を読み戻して**検証する：
`systemctl stop X` の後は `is-active` で確認する。`stop` の終了コードだけでは足りない。

## 結果の回収には完全性のゲートを設ける

被テストプログラムが結果を印字し、外側のスクリプトが回収する——
**この経路で一行落ちるのは無言で起きる。**
コンソールは BIOS のエスケープシーケンス、カーネルログ、シリアルのノイズに汚染される。
行頭で錨を打つ（`grep '^ANCHOR'`）と、行頭を上書きされた行を黙って取りこぼす。
外から見えるのは「一項目少ない」であって「失敗した」ではない。

**やり方**：被テストプログラムが最終行で「合計何件出したか」を申告し、
回収側は件数を突き合わせ、合わなければその回を破棄する。
このゲート自体も先に赤くなることを証明しておく——
N 件出したと称して N−1 件しか出さない偽プログラムを食わせ、赤にならねばならない。

## ゲート付きのスクリプトは、判定し終えてから産物を渡す

一つのスクリプトが結果を出し、それが使えるかどうかの判定も受け持つなら、**産物は判定が済んでから呼び出し側に渡す**。
先に結果を stdout に出してからゲートを走らせると、呼び出し側のリダイレクト先ファイルには、無効と判定された出力がもう保存されている——
ファイル名は呼び出し側が付けたもので、正当な産物と見分けがつかない。終了コードはエラーを報告しても、ファイルは残る。
次にディレクトリを見て回る人は、そのときの終了コードまでは確かめない。

実測（2026-09-12）：モデルの回答を取ってくるスクリプトが、本文を先に `print` してから文字化けゲートを通していた。赤判定のときは終了コード 5 で、無効版の写しを別に保存した。
それでも呼び出し側の `> …-output-s1.md` のファイルにはその本文がそのまま入っており、無効版の写しとの違いは改行一つだけだった。

**やり方**：結果はまず一時ファイルに書き、ゲートを通ってから出力する。赤判定のときは stdout を空のままにする。
このゲートも赤くなることを示す：スクリプトを「先に出力、後で判定」に戻したら、自己検査が赤くならねばならない。

## サブシェル内の代入は親プロセスに戻らない

`rc="$(run_one ...)"` の形では、`run_one` が変数に代入しても**親では空**である。
結果の回収がその変数（ログのパスなど）に依存していれば、
回収件数は永遠にゼロのまま、終了コードは 0——またひとつ、緑のまま誤る。
**値を渡すならファイルに落とすか引数で渡すこと。変数に頼らない。**

`set -u` の下ではさらに悪い。参照した側は空値を得るのではなく、その場で
「unbound variable」となり、**診断を出力する前にスクリプトを道連れにする**。
本リポジトリ自身の QEMU harness で実測された——五つの失敗分岐が `howto` を
一行も出せなかった。harness が嘘をついているときに最も必要なのが、まさにそれである。
コメントでは止められない。だから今は `scripts/shell-lint.sh` の赤くなる一項である。

## スクリプトでファイルを書き換えたら読み戻して確認する。警告はタダで得られる信号である

スクリプトで文字列置換を使ってコードや文書を書き換えるとき、
**マッチしなければエラーにはならず、ただ何も起きないだけである。**
インデントが半角スペース一つずれている、引用符の種類が違う、行末に余分な空白がある——
置換は無言で失敗し、終了コードは 0 のままである。

**やり方は二つ**：
1. **置換は命中数を検証すること**：置換件数が 0 ならエラーで終了する。「書き換えたつもり」で済ませてはならない。
2. **書き換えた後に読み戻す**：新しい内容が入っているか grep するか、実際に一度動かして挙動が変わったか確認する。

⚠️ **コンパイラや linter の警告は、この種の失敗を検知する最も安価な信号であり、見過ごしてはならない。**
実測：ある置換がインデントの不一致で反映されず、あるメソッドがデッドコードになった。
コンパイラはビルドのたびに `never used` を報告し続けていたが、
その警告は丸々一回分見過ごされ、その部分のコードから導かれた結論は**方向が逆であった。**

## パイプの終了コードは、欲しいものではない

`cmd | head` の後に `$?` を取ると、得られるのは `head` の終了コードであって `cmd` のものではない。
`cmd | grep x && do_something` も同様——判定しているのは `grep` の成否である。

結果として**失敗が飲み込まれる**：`cmd` はすでに落ちているのに、スクリプトはそのまま先へ進み、
以降の各段階は存在しない結果を前提に動く。

**やり方**：前段の成否を判定するには `${PIPESTATUS[0]}` を使うか、
そもそもパイプでつながない——先に出力を変数かファイルへ落とし、終了コードを判定してから処理する。

## テストイメージは必ず一時ディレクトリに置く

リポジトリ内には置かない。
数 GB のイメージを誤って git に入れるのは取り返しのつかない厄介事である。
イメージのパスは環境変数から取り、既定は `${TMPDIR:-/tmp}` とする。

## 破壊的な操作は、動かす前に目で確かめる

`mkfs` / `dd` / `dmsetup remove` でデバイス名を打ち間違えれば実データが消える。
**対象デバイスは変数から取り、先に `lsblk` で印字して確認すること。**
`/dev/sdX` のリテラルをハードコードしてはならない。
