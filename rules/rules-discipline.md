# 規則ファイルの鉄則

**対象**：`rules/*.md` と、プロジェクト自身の `.claude/rules/*.md`。つまり**そのとおりに実行される**文書。

設計文書は `design-doc-discipline.md`、モデルが検索して読む知識は `kb-discipline.md` に従う。
agent 定義と skill 本文も同じ鉄則に従い、検査はそれぞれ別に立てる。

## 1. 本文に書くのは四つだけ

| 書く | 書かない |
|---|---|
| どうやるか：手順、順序、判定基準、しきい値 | なぜそう決めたか：論証、トレードオフ、導出 |
| 何をして何をしないか：射程と例外 | どこから来たか：実測、日付、誰が決めたか、踏んだ穴 |
| 迷ったときの既定の選択 | 当時はどうだったか：旧い値、旧いやり方、変更の経緯 |
| どの規則がどこにあるか：他の規則・スクリプト・kb への指し示し | 門の判別力をどう示したか、その数値 |

規則は毎回の作業でまるごと文脈に読み込まれる。論証と経緯が混ざっていると、実行する側（人でもモデルでも）は
まずどの文が命令でどの文が背景かを分けねばならず、分け損ねれば背景のとおりに動いてしまう。

## 2. 判定基準は残し、論証は出す

この二つが最も混ざりやすい。分かれ目は一文だけ：

| | どんな形か | 行き先 |
|---|---|---|
| **判定基準** | それを見て、やるべきか・どこまでで終わりかが判る | **本文に残す** |
| **論証** | その判定基準がなぜ成り立つかを説明する | **消す** |

- 「この一文を消したら、読む側は何を知らなくなるか。言えないなら消す」——判定基準、残す。
- 「冗長さの代償は場所ではなく、役に立つ一文が埋もれることだ」——論証、消す。

一つの段落に両方あるときは、判定基準の一文を本文に残し、残りはまるごと消す。要約を置き去りにしない。

## 3. 出したものは消す

**専用の置き場を作らず、別のどこかに書き足しもしない。** 共有規則の履歴は従来どおり
`CHANGELOG.md` に、一版に一節。置き場はそこだけである。
消した論証がまた要るなら、もう一度論証する。

**出したあとは一字も残さない**：「（元は X）」「以前はこうだった」といった痕跡を本文に書かない。

## 4. 履歴へのリンクには制止の一句を添える

本文から `CHANGELOG.md`、`records/`、kb のその一本を指すときは、**同じ行に**制止を書く：

> 履歴と根拠：`CHANGELOG.md` の 0.0.53 の節。**由来を辿る用でなければ読むな。**

制止は「読むな」と書く。一字も省いてはならない。制止のないリンクは置いてはならない——
読む側もモデルも既定でリンクを辿り、辿った先で、いま分けて出したものを文脈に戻してしまう。

## 5. 規則ファイルに履歴の節を置かない

`CLAUDE.md` と `rules/*.md` は、末尾の `## 履歴` すら置かない。
共有規則の履歴は `CHANGELOG.md` に、一版に一節で記す。

## 6. 規則を一つ立てる前に、それが落ちる検査になるかを問う

判定基準と書き方は `sop-first.md` の「境界」の節にある。ここでは繰り返さない。

## 7. 本文で位置を指さない、自分自身も指さない

文書内の位置を指す言い方は一切書かない：「前節」「下の表」「先に述べた」「上記」「以下のとおり」「同上」「次節参照」、
および「本条」「本節」「本表」「本文書」といった自己参照も書かない。

位置は名前で書く：節はその見出し、表はそれが判定していること、
他所の事実はそれが住んでいるファイルへのリンクにする。

射程は `rules/*.md`、`CLAUDE.md`、`agents/*.md`、`skills/*/SKILL.md` であり、
判定は `kb/*.md` と同じもの、語ごとの射程は `kb-discipline.md` 第 1 条による。
規則ファイルが `<!-- doc-lint:rule-definition -->` の札を付けているとき、
バッククォートと「」の中の例は判定しないが、本文はそのまま判定する。

`scripts/doc-lint.sh` が強制する。

## 門が見ているのはどちら半分か

`scripts/rules-lint.sh` は第 1・3・4・5 条のうち字面に落ちる半分を判定する——記録の節、日付の入った行、
説明的な段落と半文、語彙的な説明、制止のない履歴リンク。走査するのはこのパッケージの `rules/`。
プロジェクトは `RULES_LINT_DIR` で自分の規則ディレクトリを渡し、共有の `gate.sh` がその段階を自動で走らせる。
まだ引き直していないファイルはプロジェクト直下の `.claude/rules-lint-exclude` に一行ずつ登録し、
済んだものから一行ずつ消す——除外は縮むだけで増えない。

第 7 条を判定するのは `scripts/doc-lint.sh` であって、`rules-lint` ではない。

**見られないもの**：第 2 条の分かれ目（どの文が判定基準でどの文が論証か）、制止の下のリンクが正しい先を指しているか。これらは意味の判断なので、人が声に出して読み、review が拾う。

⚠️ 判定の語彙は中国語である。他の言語のリポジトリでは、この検査は黙って通すのではなく
**未実装**と報告する（`show-me-test.md`：門は通ったふりをしてはならない）。
