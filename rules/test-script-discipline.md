# テストケースとテストスクリプトの書き方

プロジェクト自身の検証コードを扱う：単体テストと結合テスト、網羅や長時間ランダムによる重い検証、実デバイスや外部ツールの装置、そして入口スクリプト。入口スクリプトとは、登録した一群の項目をまとめて走らせるスクリプトをいう。一つの表、一つの入力に対して走らせるツール（位置引数が必須のもの）と、ログを読むだけの補助スクリプトは入口スクリプトではない。
これらは同じく `show-me-test.md`（新しいテストはまず赤くなることを示す）、`test-discipline.md`、`command-safety.md`、`preflight-discipline.md` に従う。

## ケースの原子化：どの一件も単独で走らせられる

**判定基準：一件のケースを名指しして単独で走らせたときと、全量の中で走らせたときとで、判定が同じであること。**

- 一件のケースに一つの場面。パラメータでループし、回ごとに被検状態を作り直すものは、パラメータを取る関数一つと値ごとのケース一件に分ける。本当に一つの場面であるもの（一つの状態の上で順に数ステップ行う）は、ケースの傍らにその理由を一行コメントで書く。
- 走る順序に依らず、他のケースが残した状態（ファイル、グローバル変数、環境変数、一時ディレクトリ）を読まない。各ケースは自分で作り、自分で消す（`command-safety.md`「テストイメージは必ず一時ディレクトリに置く」）。
- ランダムな入力にはシードを持たせる。赤のときはシードを出力し、シードだけでその一件を再現できること。
- ケース名には場面と期待する結果を書く（`code-discipline.md` の「名前」）。マイルストーン、ステップ番号、バッチといった来歴は入れず、来歴はコミットメッセージかプロジェクトの kb に書く。
- 赤になったら赤のものだけを走らせ直す：入口スクリプトは前回の出力から赤のケースを取り出し、それだけを走らせるコマンドを出せること。取り出した件数がその回の集約が報じた失敗数と合わなければ赤とし、コマンドは出さず、次の一手は「全体を一度走らせ直す」と書く（`command-safety.md`「結果の回収には完全性のゲートを設ける」）。

## 入口スクリプト：引数なしは全量

| 引数 | 何をするか |
|---|---|
| なし | 全量：高速段と低速段の全項目 |
| `--quick` | 高速段だけ |
| `--list-items` | 名指しできる項目とその段を一行ずつ列挙する。ビルドも実行もしない |
| `--item <項目>` | 名指しした項目だけを走らせる。複数回与えたら和集合 |
| 項目名の誤り、`--item` の後に項目名が無い | 名指しできる項目を列挙し、2 で終了 |

- ゲートの段階は入口スクリプトではない：`gate.sh` は引数なしで段階を起こす。段階の中でテストフレームワークを直接起こすときも入口スクリプトを呼ぶときも、段を明示する（`--quick`、`--item`、またはテストフレームワーク自身の絞り込み引数）。
- テストフレームワーク自身の印（`#[ignore]` の類）で段を分ける場合、引数なしでは印の付いたものも一緒に走らせる（`--include-ignored`）。
- 規模変数（シード数、展開の深さの類）が設定されていたら、その回の産物にその値を書き出す。全量の完了標識は規模を縮めた回を認めない。
- スクリプト全体が欠かせないツール、デバイス、ハードウェアは `run-condition`（`preflight-discipline.md`）に書き、満たさなければ 78 で終了する。一部の項目だけが必要とするものは、それらの項目を `show-me-test.md`「ゲートは通ったふりをしてはならない」に従って一件ずつ「今回は走らず」と報じ、その回は「全量通過」と言わない。
- 各項目は終わるときに一行出す：項目名、終了コード、判定した数、赤の数、再利用した数（判定を再利用する層の無い項目は「再利用なし」と書く。層はあるがこの回に数を取り出せなかった項目は「取得不可」と書き、合計に入れず、成功の一文でどの項目かを名指す。どちらも 0 とは書かない）、かかった秒数。最終行は合計。回収した項目数は `command-safety.md`「並行が失敗を飲み込んではならない」に従って照合する。
- 終了コードは 0 走ったものはすべて緑（「今回は走らず」と報じた項目があっても 0）、1 赤あり、2 使い方の誤り、77 一項目も走らなかった、78 受入条件か実行条件を満たさない（`preflight-discipline.md`）。この五つの意味は固定である。それ以外の拒否の形には別の終了コードを使ってよく、ファイル先頭に一つずつ明記する。

## テストスクリプト自身もテストで有効性を証明する

**判定基準：テストスクリプトとそれが使う判定に、どちらも自己検査があること。それらを壊すと自己検査が赤くなること**（`test-discipline.md`「検査そのものも誤りうる」と同じで、対象はプロジェクトのテストスクリプトである）。

- テストできる形に書く：判定は純関数にし、項目のドライバ、デバイス、時計、乱数源はどれも引数か環境変数で偽物に差し替えられるようにし、パスや外部サービスを決め打ちしない。差し替えられない箇所はファイル先頭に明記する。
- 自己検査は `--selftest`、同じパッケージ内のテスト、または赤緑の標本ディレクトリ（各標本に期待する終了コードと出力を書いたファイルを付ける。標本に残す空ディレクトリには `.keep` を置く。git は空ディレクトリを保存できず、ゲートの段階「スクリプトの実行ビット」（`脚本执行位`）が判定する）で行う：判定の種類（緑、赤、今回は走らず、使い方の誤り）ごとに答えの分かっている入力を少なくとも一つ与え、判定が答えと一致すること。入口スクリプトの列挙、名指し、知らない項目名の拒否、失敗の計数、項目数の照合をそれぞれ一度通す。
- 赤と判定しうる分岐ごとに壊しスイッチかミューテーションを一つ用意する：壊すと自己検査が赤くなり、名指しした項目で赤くなること。壊しスイッチはスクリプトの先頭に一つずつ明記する：スイッチ名、どこを壊すか、有効にしたときどの項目が赤くなるべきか。ミューテーションはリポジトリに入れたミューテーションリストに入れる（`show-me-test.md`「新しいテストは、まず赤くなることを示さねばならない」）。再実行する側（自己検査そのもの、またはゲートの自己検査）は一つずつ有効にし、名指しした項目で赤くなるのを見る。スイッチは自己検査だけが認め、普段の実行では認めない。
- 自己検査はゲートか高速段につなぎ、テストスクリプトや判定を変えたら走るようにする。自己検査は偽のドライバを使い、ビルドも重い作業も起こさないので、スクリプトを変える人がいつでも走らせられる。プロジェクトの重いテストを止める仕組みは自己検査を止めない。
- 自己検査も「ケースの原子化：どの一件も単独で走らせられる」を守る。

## 高速と低速の二段に分ける

| 段 | 何を入れるか | いつ走らせるか |
|---|---|---|
| 高速段 | プロジェクトの定めた速い・遅いの判定基準で速いとされたケースと、必ず高速段に入れる種類 | 変更のたび |
| 低速段 | 速い・遅いの判定基準で遅いとされたケース：網羅、長時間ランダム、実デバイス、外部ツールの類 | 全量と一緒に：コミット前かユーザーの求めがあったとき。それ以外の時機はプロジェクトが定める |

- 速い・遅いの判定基準と二段それぞれのコマンドはプロジェクト・ローカルの規則に書く。判定基準は一項目の所要時間の閾値（普段走らせたときに測れた数で判じる）でもよく、網羅するか、実デバイスや外部ツールが要るかで分けてもよい。迷うものは低速段に回す。
- 段はケースの上か登録表に印を付け、スクリプトの中に別の名簿を写さない。
- 速い・遅いの判定基準に関わらず必ず高速段に入れる種類：低速段の判定方式ごとの小入力ケース（同じ判定、小さい入力）、枝刈りの自己検査、マルチスレッドとシングルスレッドの突き合わせ、最適化前後の突き合わせ、加速経路と参照経路の突き合わせ、全量から固定し戻した赤の例。特定のハードウェアが要るものは、そのハードウェアの無いマシンでは「今回は走らず」と報じる。
- コンパイルスイッチ（フィーチャー、`cfg` の類）で段を分ける場合、高速段の少なくとも一回はそれを組み込んでビルドする。ある種類が組み込まれて 0 件なら「今回は走らず」と報じ、走ったことにはしない。

## 判定を再利用できる形に：入力で保存し、接頭辞で刈る

- 判定はどれも、それが依存する入力すべて（被検コード、判定コード、パラメータ、ツールチェーン）から計算した鍵で保存する。鍵が同じなら再計算せずに再利用する。
- 判定の保存庫はその回の出力ではない：出力は `show-me-test.md`「ゲートは通ったふりをしてはならない」に従って回ごとに新しく書き、再利用した判定は今回判定したものと分けて出力に報じる。保存庫の置き場所は `command-safety.md`「テストイメージは必ず一時ディレクトリに置く」の実行をまたいで再利用するキャッシュの一文に従う。
- 状態空間は共有する接頭辞で組み立てる：複数の流れや項目が共有する接頭辞は一度だけ判定し、続きはその上で判定する。
- 刈り取ってよいのは二種類だけ：鍵が同じで既に判定済みのもの、既に判定した状態と等価なもの。等価関係はケースにして固定する。
- 登録によって一括で判定しない種類は枝刈りではない：登録表は一種類一行で判定しない理由を書き、成功の一文は飛ばした数を報じ、`show-me-test.md`「ゲートは通ったふりをしてはならない」に従って判定しなかった種類を列挙する。
- 枝刈りには自己検査を付ける：小規模な入力で枝刈りと再利用を切って一度走らせ、入れたときと判定が項目ごとに一致すること。枝刈りの自己検査は高速段に入れる。
- 一ブロックを判定し終えてからディスクに書き、書き込みは原子的に行う。中断された後は同じコマンドを走らせ直せば続きからになり、未判定の分だけを埋める。
- 成功の一文は「今回判定 N、再利用 M」を報じる。
- スクリプト全体の入力が変わっていなければ走らせ直さない。`admission: inputs-changed` と書く（`preflight-discipline.md`）。判定単位の再利用はスクリプトの中で行う。両方の層が要る。

## ビルドもアルゴリズムも速く

- 重いケースは最適化ビルドで走らせ、オーバーフロー検査とアサーションは入れたままにする（Rust：`opt-level = 3` に `overflow-checks = true`、`assert!` はすべて残す）。デバッグビルドでだけ効くアサーション（`debug_assert!` の類）を入れるかどうかは、プロジェクトが代価を測ってから決め、切るならビルド設定の傍らに測った代価を書く。
- 一回の実行でビルドは一度だけ：複数の項目が一つのビルドを共有する。ビルド産物は回をまたいで再利用し（置き場所は `command-safety.md`「テストイメージは必ず一時ディレクトリに置く」の実行をまたいで再利用するキャッシュの一文に従う）、走らせる前に消さない。
- ホットパスでは判定と無関係なことをしない：整形、一件ごとのログ、繰り返しの確保。
- プロセス内で互いに独立した単位は区間で切って並行に走らせ、並行度は `command-safety.md`「一つのスクリプトの中の検査項目は、並行にできるなら並行にする」に従う。合併は決定的に：計数はスライスの順に足し、「最初の一つ」は番号が最小のものを取る。マルチスレッドとシングルスレッドの突き合わせは一字一句同じで、高速段に入れる。並行にできないもの（状態の共有、順序そのものが被検対象）は、そのケースのコメントに理由を書く。
- プロジェクトの定めた進捗間隔より長く走る項目は、間隔ごとに少なくとも一行の進捗を出す：スライスごとに区間と判定済みの数を出す。
- 最適化で判定基準を差し替えてはならない：最適化の前後で同じ入力の組に対する判定が項目ごとに一致し、その突き合わせを高速段に入れる。

## 手元のハードウェアで加速する

- どの種類の計算を加速ハードウェア（GPU の類）に回すか、どのマシンを使うか、それぞれにどれだけ割り当てるかは、プロジェクトのローカル設定に登録する。登録した種類は加速経路だけを通し、設定したマシンの台数だけ分ける。
- 設定で有効にしたハードウェアやマシンをスクリプト全体が欠かせないなら、`run-condition: check` に書く：使えない（デバイスが無い、ドライバが合わない、カーネルがビルドできない、デバイスメモリが足りない、二台目に繋がらない）ときは 78 で終了し、次の一手は「デバイスを直すか、設定を変える」と書く。黙って CPU や一台に戻さない。戻すなら設定を変えるか、明示的に引数で渡す。
- 加速経路には CPU の参照実装を残し、同じ入力の組で両者の判定が一件ずつ一致すること。この突き合わせは高速段に入れる。
- 加速経路もまず赤くなることを示す：加速側に既知の故障を入れ、突き合わせが赤くなること。

## 全量の赤は高速段に固定し戻す

- 全量で赤が一つ出るたびに、それを引き起こした入力を高速段のケース一件か登録表の一行にし、高速段で判定し直す。修正した後も回帰として残し、消さない。
- 固定する前に、縮められるなら赤のままである最小の入力まで縮める。縮められないものは理由を書き、そのまま固定する。固定したら一度確かめる：赤の出たコードの上で、固定したケースも赤くなり、同じアサーションで赤くなること。
- プロジェクトは固定表を一つ持ち、一件固定するごとに一行登録する：赤の出た行を丸ごと写し産物のファイル名を添え、どこを戻せば（ミューテーションかそのコミット）赤くなるかを書く。
- 全量の産物にある赤のどれにも固定表に対応する行が見つかって、はじめて閉じたことになる。

## ゲートが見るのはどちら半分か

**共有の検査になったものはまだ一つも無い。** 字面で判じられるものは、プロジェクトが `.claude/gate.d/` にローカルの段階をつないで判じられる：
入口スクリプトの引数の約束（`--list-items` が 0 で終わり、ビルドも重い作業も起こさない、項目名の誤りで 2 で終わる）、自己検査（三つの形のいずれか）があって走らせると緑か、ファイル先頭に明記した各壊しスイッチを有効にしたとき自己検査が名指しした項目で赤くなるか、全量の産物の赤がすべて固定表にあるか、パラメータのループがケースに分けられているか、必ず高速段に入れる種類の突き合わせが高速段にあるか。

レビューに任せるもの：自己検査が判定の種類を漏れなく覆っているか、ケースが本当に互いに独立しているか、再利用の鍵が入力をすべて覆っているか、枝刈りの等価関係が正しいか、速い・遅いの判定基準が妥当か、ホットパスで判定と無関係なことをしていないか、加速ハードウェアに回すべき計算がすべて登録されているか、固定したケースと全量の赤が同じ欠陥であるか。
